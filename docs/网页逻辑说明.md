# 个人ERP管理系统 · 网页逻辑说明

> 技术栈：Python Flask（后端 API）+ 原生 HTML/CSS/JS（前端）+ SQLite / PostgreSQL（数据）
> 部署：Docker（gunicorn 2 worker）+ Cloudflare Tunnel 外网访问

## 一、页面结构

| 页面 | 路径 | 功能 |
|------|------|------|
| 登录页 | `/login.html` | 账户登录，支持主题切换、Enter 登录 |
| 物料管理 | `/`（index.html） | 物料查询 / 新增 / 编辑 / 删除，LCSC 立创商城联动，手册与图片管理 |
| 出入库 | `/stock.html` | 入库 / 出库操作与流水记录查询 |
| 仓库管理 | `/warehouses.html` | 仓库树（1~4 级）的建立 / 改名 / 删除 |
| 系统管理 | `/system.html` | 数据库信息与备份、账户管理、**版本更新（GitHub）** |

所有页面共用侧栏导航（`common.js → renderNav()`），侧栏在 HTML 解析阶段即注入（`nav-mount` 内联脚本），保证首帧渲染不闪跳。

## 二、认证与会话

- 登录：`POST /api/login` → 校验 `users` 表（SHA-256 密码哈希）→ 写 Flask session cookie
- 鉴权：后端 `@login_required`（需登录）/ `@admin_required`（需管理员）装饰器
- 前端：`common.js → api()` 统一封装，收到 401 自动跳转 `/login.html`
- 会话密钥：固定 SECRET_KEY（环境变量可覆盖）。**注意：多 worker 下用随机密钥会导致登录后被踢回登录页**
- 默认账户 admin/admin123：登录页通过 `GET /api/default_admin_exists` 探测，**仍是默认密码才显示提醒**，改密后提示自动消失

## 三、数据层（db.py）

- 双后端抽象：`DB_TYPE=sqlite` 或 `postgres`（`POSTGRES_DSN` 连接串）
- 占位符统一写 `?`，postgres 后端自动转 `%s`；INSERT 自动追加 `RETURNING id`
- 启动时自动：`init_schema()` 建表 → `ensure_default_admin()` 建 admin → `run_migrations()` 补列/迁移
- 文件存储：手册 PDF、物料图片全部以 BLOB 存数据库（postgres 用 BYTEA），查看时从内存还原返回，不依赖本地文件夹

### 核心表

- `users`：账户（username / password_hash / role）
- `warehouses`：仓库树（id / name / parent_id，最深 4 级）
- `materials`：物料（编码、规格、图片 BLOB 等）
- `material_documents`：物料手册（file_blob、文件名、类型）
- `stock_records`：出入库流水（物料、数量、方向、经手人、时间）

## 五、版本更新机制（GitHub 在线更新）

**流程**：系统管理页 → 「检查更新」→ 对比 GitHub 分支最新 commit 与本地 `.version` → 有新版则「一键更新」：

1. 下载仓库 tarball（`codeload.github.com`，支持私有仓库 Token 与加速代理）
2. 解包覆盖到应用目录；**跳过** `.env / data / uploads / .git / .version`（数据与环境绝不覆盖），并防目录穿越
3. 写入新版本号到 `.version`
4. 向 gunicorn 主进程发 SIGHUP 平滑重启（不断服务），页面 8 秒后自动刷新

**环境变量**：

| 变量 | 说明 |
|------|------|
| `GITHUB_REPO` | 仓库，格式 `用户名/仓库名`（如 `Liaojianwei8/AP_ERP`） |
| `GITHUB_TOKEN` | 私有仓库必填；fine-grained PAT，只给该仓库 Contents:Read-only |
| `GITHUB_PROXY` | 可选加速前缀（如 `https://gh-proxy.com`），GitHub 直连不稳时用 |
| `GITHUB_BRANCH` | 分支，默认 `master` |

**安全**：Token 只存于 NAS 容器环境变量，经 HTTPS 传输（抓包仅见 github.com 域名，看不到内容）；fine-grained PAT 只读单仓库，即使泄露也无法改代码。

## 六、前端交互细节

- **主题**：三套（经典/洁净/暗夜），CSS 变量 + `html[data-theme]` 切换，localStorage 持久化；各页 head 内联脚本提前应用防闪白
- **页面切换**：`@view-transition { navigation: auto }` 跨文档视图过渡，切换丝滑不闪
- **防抖动**：侧栏 nav-mount 内联注入，首帧即渲染完整布局
- **表格/表单**：物料列表分页加载；新增/编辑用模态框；危险操作（删除）二次确认

## 七、部署与更新（NAS / fnOS）

- 容器：`personal-erp`（gunicorn `-w 2 -b 0.0.0.0:5000`），数据库用宿主机 postgres（54321）
- 局域网访问：`http://NAS_IP:54322`；外网：Cloudflare Tunnel → `https://erp.445300.xyz`（Service 指向 `127.0.0.1:54322`）
- **日常更新**：网页 → 系统管理 → 检查更新 → 一键更新（无需 SSH、无需手动传文件）
- **改代码后的发布**：本地提交并 push GitHub → NAS 网页点一键更新即可

## 八、AI 助手 + 采购清单 模块（2026-10，v261015.6）

### 新增页面
- **AI 助手（/chat.html）**：对话式完成物料查询 / 出入库 / BOM 核对 / 采购管理。
  - 历史记录落库 `chat_messages`（每人独立），向上滚动翻页加载
  - 写操作（建料/出入库/导入采购）AI 只能生成**待确认卡片**，用户点「确认执行」才落库（operator 留痕 `ai:用户名`）；卡片状态机 pending→executed/cancelled/failed，非 pending 重复确认返回 409；库存不足保持 pending 可补货后重试
  - AI 接口在 系统管理页 配置（OpenAI 兼容：DeepSeek / Kimi / GLM 预设可改），存 `app_settings` 表，key 打码回显
### 采购清单（/purchase.html）
- 顶部 BOM 核对面板：粘贴多行（Tab/逗号/空格分隔，自动识别立创C编号与行尾数量）→ 可编辑预览 → 核对 → 勾选缺料一键导入采购清单并归档项目名
- 采购条目按项目 tab 分组：需求量 / 已购量 / 缺口 / 状态徽标（open未采/partial部分/done完成）
- **分批采购**：每笔采购登记一条批次（数量+备注），已购 = SUM(批次)；删批次自动回退状态；状态读时派生不存列
- 同项目同物料（material_id 或非空 code 相同）再次导入自动合并累加需求量
### 物料自动补全（双端建料/编辑时）
- 编码为立创C编号（如 C621395）时自动抓取：图片、数据手册、名称/型号/品牌/封装/分类/商城链接——**仅在字段为空时填充，绝不覆盖已填内容**；失败静默不阻塞
- 本地版下载文件存数据库 BLOB；云端版存外链（302 跳转立创 CDN，无需 R2）
### 物料列表 sticky 出入库列
- index.html / stock.html 表格最右侧「入库/出库」按钮列固定（position:sticky），横向滚动时始终可见

### AI tool loop 设计要点
- 9 个工具：search_materials / list_warehouses / lcsc_search / check_bom / query_purchase 只读真执行；create_material / stock_in / stock_out / add_purchase_items 写操作拦截转卡片
- 双保险上限：LLM 轮次 ≤8、工具调用 ≤12；轮次用尽追加一次不带 tools 的请求逼出文本总结
- 历史重放降级：入库的 assistant 消息剥 tool_calls、卡片拼成文字摘要，避免发给模型缺 tool 消息报 400
- 云端镜像：cloudflare/src/ai.ts（对话）、routes.ts（配置/采购）、core.ts（共享核心）与 Flask 版 1:1
